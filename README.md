# 部室の鍵ボード

部室の鍵を「誰が借りたか」「部室は開いているか」「閉まっているなら鍵は誰が持っているか」を、部員みんなでリアルタイムに共有するWebアプリです。

- 画面: GitHub Pages（静的ファイルだけ）
- データ・ログイン: Firebase（Firestore + Googleログイン）
- 複数の部活で使えます。部活ごとに招待コードで部員を管理します。

## できること

- 鍵の状態（**借りた / 持っている / 返した**）と部室の状態（**開いている / 閉まっている**）をランプで表示
- 操作ボタン: 鍵を借りた・部室を開けた・部室を閉めた・守衛さんに返した・自分で持っている・鍵を別の人に渡した
- すべての操作に確認画面。直前の操作は「取り消す」で戻せる（後から別の操作が入ったら戻せない）
- 「自分で持っている」は返却時刻と「家に持ち帰らない」チェックが必須
- 最終返却時刻を過ぎて鍵が戻っていない、前日から返っていない、施錠後に返却も保持宣言もない、などで警告
- 履歴（誰がいつ何をしたか）、記録の訂正
- 管理者メニュー: 部活名・鍵番号・最終返却時刻の設定、招待リンク、部員の権限変更・削除

## セットアップ

### 1. Firebase プロジェクトを作る

1. <https://console.firebase.google.com/> で「プロジェクトを追加」。無料の Spark プランで動きます。Google アナリティクスはオフで構いません。
2. 「プロジェクトの概要」→ ウェブアプリ（`</>`）を追加。表示された `firebaseConfig` の中身を `firebase-config.js` に貼り付けます。
3. **Authentication** →「始める」→「ログイン方法」で **Google** を有効にします。
4. **Authentication →「設定」→「承認済みドメイン」** に `あなたのユーザー名.github.io` を追加します（`localhost` は最初から入っています）。
5. **Firestore Database** →「データベースを作成」。ロケーションは `asia-northeast1`（東京）がおすすめ。本番環境モードで作成します。
6. Firestore の **「ルール」タブ** に `firestore.rules` の中身を貼り付けて「公開」。
   - Firebase CLI を使う場合は `firebase deploy --only firestore:rules` でも反映できます。

### 2. GitHub Pages で公開する

1. GitHub に新しいリポジトリを作り、このフォルダのファイルをすべて push します。
2. リポジトリの **Settings → Pages** で「Deploy from a branch」、ブランチ `main`、フォルダ `/ (root)` を選んで保存。
3. 数分後に `https://あなたのユーザー名.github.io/リポジトリ名/` で開けます。

### 3. 使い始める

1. 公開したURLを開いて Google でログイン。
2. 「新しく部活を登録する」で部活ID（例: `light-music`）・名前・鍵番号・最終返却時刻を入れて登録。登録した人が作成者（管理者）になります。
3. ボード下の「管理者メニュー」→「招待リンク」をコピーして部員に送ります。
4. 部員はリンクを開いて Google でログインし、表示名を入れて「参加する」を押せば使えます。

部活ごとのURLは `https://…/リポジトリ名/?club=部活ID` です。守衛室や部室のドアにこのURLのQRコードを貼っておくと、押し忘れが減ります。

## 手元で動かす

ES Modules を使っているので、ファイルを直接開くのではなくローカルサーバーで開いてください。

```sh
python3 -m http.server 8000
# http://localhost:8000/ を開く
```

## データの構造（Firestore）

```
users/{uid}                        自分が参加している部活の一覧
clubs/{clubId}                     部活名・鍵番号・最終返却時刻・作成者
clubs/{clubId}/private/invite      招待コード（管理者だけ読める）
clubs/{clubId}/members/{uid}       部員（role: admin / member）
clubs/{clubId}/state/main          鍵と部室のいまの状態
clubs/{clubId}/log/{id}            履歴（取り消し用に操作前後の状態も保存）
```

## 権限（firestore.rules）

| 誰が | できること |
|---|---|
| ログインした人 | 部活の登録、部活IDを知っていれば部活名の表示、正しい招待コードでの参加 |
| 部員 | ボードの閲覧・記録・取り消し・訂正、自分の表示名の変更、脱退 |
| 管理者 | 上記に加えて、部活の設定、招待コードの作り直し、部員の権限変更・削除、履歴の削除 |
| 作成者 | 管理者と同じ。降格・削除はされない |

## メモ

- `firebase-config.js` の `apiKey` などはブラウザに公開される前提の値で、秘密情報ではありません。データを守っているのは `firestore.rules` です。
- 今は Google アカウントがあれば誰でも新しい部活を登録できます。荒らしが気になる場合は、ルールの `clubs/{c}` の `allow create` に許可するメールアドレスの条件を足すか、Firebase App Check を有効にしてください。
- 時刻の判定（最終返却時刻・30分警告など）は各自のスマホの時計で行っています。
- 記録は自己申告です。実際の鍵の受け渡しと必ずセットで押してください。
